# 우사기 캐릭터

설정 → 캐릭터 → **우사기**를 고르면 앱 이름·기본 문구·AI 말투가 함께 바뀐다. v0.4.0부터 우사기 그림·영상은 레포와 앱에 들어 있지 않다. 그림은 사용자가 설정 창에서 직접 넣고, 넣지 않으면 기본 그림으로 보인다. 기본 캐릭터는 기존처럼 시사다. 사용자가 직접 저장한 문구와 AI 말투는 그대로 우선한다.

## 자료 조사와 각색의 경계

2026-10-16에 아래 자료를 확인했다. 한국어 문장은 이 앱을 위한 새 각색이며 원작 대사의 번역이 아니다.

| 근거 | 확인한 내용 | 앱에서의 선택 |
|---|---|---|
| [애니메이션 공식 캐릭터 소개](https://www.anime-chiikawa.jp/chara.html) | 치이카와의 친구. 「ウラ」「ヤハ」 등의 큰 외침을 자주 쓴다. 성우는 오자와 아리. | 사람말을 직접 하는 각색을 없애고 외침으로 반응한다. 필요한 뜻은 괄호에 따로 적는다. |
| [영문 공식 캐릭터 소개](https://www.chiikawaofficial.com/characters/) | 활기차고 겁이 없으며 재미를 찾아 움직이는 성격으로 소개한다. | 외침에 활기를 담고 괄호 속 설명으로 작은 행동을 제안한다. 위험한 작업을 멋대로 실행하는 성격으로 해석하지 않는다. |
| [CCP 라이선스 상품 보도자료](https://www.ccp-jp.com/pdf/20250307.pdf) | 겁이 없고 늘 활기찬 캐릭터라는 소개와 권리자 표기. | 활기를 살리되 사용자에게 무리한 낙관이나 압박을 주지 않는다. |
| [후지TV 제작자 인터뷰, 2024-08-07](https://www.fujitv.co.jp/company/fujitvwork/vol25.html) | 원작의 정지 장면을 애니메이션으로 옮기며 우사기의 점프·회전 같은 세부 동작을 고민한다는 설명. | 알림·춤·응원은 가벼운 홉과 좌우 움직임. 공식 영상의 동작을 재현했다고 주장하지 않는다. |

공식 소개의 일본어 문구는 페이지가 불러오는 `js/main.js`의 `code: "usagi"` 항목에서도 확인할 수 있다. 영문 소개의 거주지 설명은 시점에 따라 달라질 수 있어 사용하지 않았다.

[팬의 말버릇 정리](https://chiikawa.hatenablog.jp/entry/2021/12/03/143810)는 원작 링크를 찾는 보조 자료로 봤다. 연결된 원작 X 게시물은 열람이 제한되어 직접 검증하지 못했다. 따라서 `プルャ`의 특정 번역, 자격증 등 세부 설정, 성별·나이·정체·능력에 관한 추측을 프롬프트에 넣지 않았다. `하아~~?`는 의문·확인 질문에 쓰되 사용자를 비웃거나 공격하는 뜻으로 쓰지 않는다.

## 말투

우사기는 **외침 + 괄호 속 의도 설명**으로 반응한다. 괄호 밖에는 `우나`, `야하!`, `푸루루루루루루루`, `이야하~!!!`, `우라라 야하.`, `하아~~?` 같은 외침만 두고, 전달할 한국어는 괄호 안에 적는다. 이 표기는 기여자가 요청한 한국어 표현을 앱에 적용한 것이며, 괄호 안은 앱에서 새로 쓴 뜻 설명이다. 외침의 고정 번역이나 원작·한국어판의 정식 대사라고 주장하지 않는다.

인사·할 일·응원·일정·설치·둘러보기·승인 질문에 같은 형식을 쓴다. 의문·확인은 `하아~~?(뭐라고?)`처럼, 완료·응원은 `야하!(수고했어!)`처럼 표현한다. 정보 전달이 없는 춤은 요청한 외침을 두 줄로 표시한다. 완성된 문구에 별도의 앞말·꼬리말을 붙이지 않는다.

| 상황 | 예시 | 의도 |
|---|---|---|
| 인사 | 우나 야하(우사기 왔어. 오늘 할 일부터 볼게!) | 활기와 등장감 |
| 남은 할 일 | 우나 야하(오늘 할 일이 3개 남았어.) | 실제 개수 전달 |
| 다음 할 일 | 우나 야하(먼저 '보고서'부터 보자!) | 작게 시작하도록 제안 |
| 집중 완료 | 이야하~!!!(25분 동안 집중했어. 잠깐 기지개 켜자!) | 실제 전달받은 시간만 말함 |
| 피곤할 때 | 우나(잠깐 멈춰도 돼. 물 한 모금부터!) | 재촉 대신 휴식 |
| 춤 | 이-야~ 야하 야하!<br>우-라 푸루푸루푸루!! 우라~! | 랩 동작에 맞춘 두 줄 외침 |
| 일정 | 우나(〈주간 회의〉 10분 전이야. 15:00 · 회의실 A) | 제목·시각·장소가 중심 |
| 머지 승인 | 하아~~?('수정' PR을 머지할까?) | 선택을 분명하게 물음 |
| 확인이 필요한 상황 | 하아~~?(어느 할 일을 말하는 거야?) | 질문의 뜻을 괄호에 명시 |

AI의 `tone`과 `persona`에는 같은 형식을 지시한다. 이는 모델 지시이며 출력 후처리로 강제하는 방식은 아니다. `bubble`·`reply_md`·`reply` 같은 사용자 표시 대사에만 적용하며 제목·id·시각·명령·도구 인자·상태 값과 JSON 구조는 바꾸지 않는다. 기존 오류·권한 규칙도 유지한다. 사용자가 직접 고친 말투·문구·캐릭터 대사 덮어쓰기는 그대로 우선한다.

고정 문구 40종, 로컬 답변 21종, 응원, 패널의 정해진 답, 설치 12단계 문구, 오버레이 5종, 사용법 11종을 모두 `assets/characters/lines.json`에 채웠다. 대사·AI 지시·보안 규칙은 구분되어 있으며 캐릭터 선택으로 권한이나 승인 정책이 바뀌지 않는다.

## 그림

v0.4.0에서 우사기를 포함한 기본 캐릭터 그림·영상과 그 원본(`artwork/usagi/`)을 레포에서 뺐다. 이 문서는 말투와 대사만 다룬다.

## 구현과 검증

- 등록: agent `characters.ts`, desktop `character.js`와 `assets.js`에 같은 `usagi` id를 쓴다. 설정·SSE·앱 이름·메뉴·설치 화면은 기존 캐릭터 선택 경로를 따른다.
- 대사: `assets/characters/lines.json`에 우사기 항목을 추가하고 `sync-character-lines.mjs`로 렌더러 사본을 생성한다. 직접 저장한 문구와 AI 말투는 기존처럼 우선한다.
- 그림: 레포에는 없다. `assets/characters/clips.json`의 우사기 칸(`study`·`plan`·`dance`·`cheer`·`lunch`)은 예전 버전이 사용자 폴더에 깔아 둔 영상이 있을 때만 쓰인다.
- 회귀 검사: 설정 저장·재시작·사용자 문구 유지, 렌더러 상태 수신, 예전 그림 이름의 허용 목록을 검사한다. 기존 캐릭터도 같은 검사에 포함한다.

춤 대사는 줄바꿈을 포함한 다음 두 줄이다. 캐릭터 위 질문 칩과 채팅의 정해진 답에 같은 기본 문구를 둔다.

```text
이-야~ 야하 야하!
우-라 푸루푸루푸루!! 우라~!
```

패널에서 머리 위로 답을 전달하는 공통 동작은 이 캐릭터 추가의 변경 범위에 포함하지 않는다.
